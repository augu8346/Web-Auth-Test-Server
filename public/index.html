02

Import on your Windows host

These PowerShell commands save test assets under your user profile. CurrentUser trust does not require administrator privileges. Import the CA, not the server leaf certificate.

Restart ArcGIS Pro or your client after importing. Services running under another account need that account's trust store, or an administrator-managed LocalMachine root store.

03

Verify without skipping TLS

Windows Schannel clients use the Windows certificate store. OpenSSL-based clients may instead require an explicit CA file.

This test CA has no revocation service. Schannel can report "revocation status is unknown"; --ssl-revoke-best-effort allows unavailable revocation metadata without disabling CA, expiry or hostname validation. Do not substitute -k.

The generated certificate covers localhost and 127.0.0.1 only. Trusting the CA does not fix a hostname mismatch. Remote access needs a certificate with the actual DNS name/IP in its SANs.

Docker persistence, client certificates & removing trust

Certificates survive container rebuilds

The Compose service mounts ./certs at /app/certs. Startup generates a full certificate set only when none exists; it reuses a complete set and rejects partial sets. You do not need to import the CA after every restart. Running npm run generate-certs explicitly replaces the set; restart the server, download the new assets, and replace the old trust entry.

If downloading is inconvenient, run docker compose cp auth-server:/app/certs/ca.crt .\ca.crt from the project directory. Always import onto the host where the client runs.

Server trust and client identity are different

The root CA validates the server. The PEM certificate + key or PKCS#12 bundle identifies your client for mTLS. Importing the root alone does not provide client authentication. The downloadable client key is deliberately public test material; CA and server private keys are never downloadable.

Remove test trust when finished

In certmgr.msc, open Trusted Root Certification Authorities / Certificates, inspect the thumbprint, and remove only the matching Mock Auth Testing CA entry. Do not remove unrelated roots.

04 / REFERENCE

Know what you are testing.

Byte ranges & Brotli

Ordinary TIFF endpoints support GET, HEAD, and byte ranges: a valid range returns 206 and Content-Range; an unsatisfiable range returns 416. The separate Brotli case uses HTTP Content-Encoding, not TIFF-internal compression. When the client accepts br, it returns the complete encoded stream with 200 and Accept-Ranges: none, even if a Range header is present. Without br support it serves the ordinary identity TIFF with range support. Prefer full downloads or GDAL /vsicurl_streaming/ for Brotli; /vsicurl/ random access is not the purpose of that case.

OAuth is a transport mock

The token endpoint accepts POST bodies and returns a fixed bearer token. It does not validate client secrets, authorization codes, redirect URIs, PKCE verifiers, scopes, or grants, and does not enforce expiry or refresh. The authorization endpoint returns a fixed code. Use it to test client wiring and token propagation, not OAuth security, rejection behavior, or token renewal.

401, 403, or TLS failure?

401: check the Basic/bearer fields, or supply a client certificate for mTLS. 403: a presented client certificate is not trusted by this server. TLS validation failure: confirm the active CA, certificate dates, and hostname. A TLS handshake failure can occur before HTTP and will not appear in request logs. Do not use GDAL_HTTP_UNSAFESSL=YES as the normal configuration.

Docker ports & other machines

Compose publishes 9480 and 9443 on loopback only. For a deliberately shared test deployment, change the bind addresses, configure firewall rules, and issue appropriate SAN certificates. Set PUBLIC_HTTP_URL and PUBLIC_HTTPS_URL to the client-visible origins if port mappings or a reverse proxy differ from the internal ports. Clients inside another container cannot reach this container using their own localhost.

Custom headers & cookies

No-auth routes accept arbitrary headers and cookies without requiring them. In GDAL use GDAL_HTTP_HEADERS for custom headers and GDAL_HTTP_COOKIE for cookies. Inspect Live request logs to confirm what was sent. Set these options only for the intended test and clear them before testing another authentication profile.

Automated verification

From the project directory, run npm test against the running server. The suite validates TLS with the generated CA, authentication rejection and success, both no-auth protocols, byte-exact ranges, Brotli decompression, certificate downloads, and OAuth request wiring. HTTP_PORT and HTTPS_PORT override local test ports; TEST_HTTP_URL, TEST_HTTPS_URL, and TEST_CERTS_DIR target another deployment.
